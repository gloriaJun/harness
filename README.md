# grimoire

Source of truth for my user-level AI coding environment: Claude Code
configuration (instructions, skills, hooks, agents, statusline) plus a
generated Codex CLI surface. Nothing under `~/.claude/` or `~/.codex/` is
edited by hand - everything is authored here and copy-synced on commit.
v1 (symlink-based) is preserved on the [`v1`](../../tree/v1) branch.

## Fresh machine setup

```bash
git clone git@github.com:gloriaJun/grimoire.git
cd grimoire
./bootstrap.sh          # add --dry-run to preview
```

`bootstrap.sh` is idempotent: it checks required tools (git, jq, rsync),
wires the post-commit hook (`git config core.hooksPath githooks`), runs both
syncs, seeds `~/.codex/config.toml` from the template, and installs every
external dependency declared in `external.json` (plugin marketplaces,
plugins, third-party skills). Re-run it any time; satisfied steps are
skipped. Plugin and skill changes apply from the next Claude Code session.

## How sync works

Committing anything under `claude/` or `ccstatusline/` triggers
`githooks/post-commit`, which runs `sync.sh` then `codex-sync.sh`
("committed = live"; the working tree state is what gets synced). Preview
with `./sync.sh --dry-run` and `./codex-sync.sh --dry-run`.

| Source | Destination | Mode |
|---|---|---|
| `claude/instructions/shared/*.md` | `~/.claude/AGENTS.md` | assembled (filename order); tool-neutral body shared with Codex |
| `@AGENTS.md` import line + `claude/claude-only.md` | `~/.claude/CLAUDE.md` | stub; Claude expands the import at launch |
| `claude/instructions/`, `claude/hooks/`, `claude/agents/` | same paths under `~/.claude/` | full mirror with `--delete` |
| `claude/skills/g-*` | `~/.claude/skills/g-*` | per-entry mirror; `l-*` belongs to the company repo, other names warn-only |
| `claude/settings.hooks.json`, `claude/settings.statusline.json` | `hooks` / `statusLine` keys of `~/.claude/settings.json` | jq merge, other keys untouched |
| `claude/settings.mcpServers.json` | user-scope MCP servers in `~/.claude.json` | applied by `bootstrap.sh` via `claude mcp add-json --scope user`; `sync.sh` only warns on drift (Claude reads MCP config from `~/.claude.json`, not settings.json, and that file also holds runtime state) |
| `ccstatusline/` | `~/.config/ccstatusline/` | rendered (`{{HOME}}` substituted) |
| `claude/instructions/shared/*.md` + company workspace CLAUDE.md | `~/.codex/AGENTS.md` | generated by `codex-sync.sh` (full copy: Codex has no import syntax) |
| `~/.claude/skills/*` (minus excludes) | `~/.codex/skills/` | migrated by `codex-sync.sh`, manifest-owned |

## External installs

`external.json` declares the desired plugin marketplaces, plugins, and
third-party skills; `claude/settings.mcpServers.json` declares user-scope
MCP servers (an entry with `disabled: true` is declared but not installed).
`bootstrap.sh` installs whatever is missing and reports live entries
outside the manifests without touching them. Company marketplaces and
plugins are deliberately absent - they are managed by the company repo.

## Layout

- `claude/` - the synced payload (instruction fragments, references, hooks,
  skills, settings fragments)
- `sync.sh`, `codex-sync.sh`, `githooks/post-commit` - sync mechanism
- `bootstrap.sh`, `external.json` - fresh-machine setup + external-install
  manifest
- `ccstatusline/` - statusline widget config
- `bin/cwt` - git worktree + Claude launcher CLI (symlinked from
  `~/.local/bin/cwt`)
- `templates/` - per-machine config skeletons
- `tools/doc-viewer/` - bilingual (EN source / KO overlay) static viewer for
  the definition files; `dist/` and `translations/` are generated

## Conventions

Definition files under `claude/` are English-only and size-budgeted
(enforced by `claude/hooks/definition-check.sh`); Korean readability comes
from the doc viewer. See `CLAUDE.md` for the working rules Claude Code
itself follows in this repo.
